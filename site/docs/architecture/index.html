🧭 Architecture

Architecture

Author once. Compile per harness. Enforce the workflow at the tool boundary.

One mental model to keep: you write the crew and commands once, in a neutral form; the shipmates CLI compiles them for each harness with only the features that harness supports; and a small state machine enforces the workflow through the harness's own tool hook — falling back to advice where there is no hook.

The big picture

Three layers, one direction of travel: neutral sources in, a native payload out, and a workflow that can be enforced at the far end.

Everything below is just those three boxes in more detail. Nothing harness-specific lives in the sources; nothing neutral survives into a payload unchanged.

One source of truth

The 12 crew, 12 commands and the tools are written once, in a harness-neutral dialect.

crew/*.md are the twelve specialist subagents; commands/*.md are the twelve workflows; toolbox/* are the model-invoked tools. They are domain-neutral by rule — no stack, framework or product is named, and $ARGUMENTS is the only placeholder a command may carry.

These are the only files you edit for crew or command content. Every harness's payload is rendered from them, so a change made once reaches all eight.

Feature-aware adapters

One Rust adapter per harness gives each target exactly what it can use — and nothing it can't.

The shipmates CLI is a single binary that embeds the canonical sources and compiles them through an adapter per harness (src/adapters/<harness>.rs). Each adapter knows its harness's native file shape and frontmatter dialect, its real install paths (.claude/, .opencode/, .agents/skills/, .codex/, .github/, .windsurf/, .cursor/), and its least-privilege tool scopes.

Crucially, an adapter emits only the features that harness actually supports — per-agent model and reasoning effort, subagents versus skills-only — recorded in tools/harness_matrix.json and checked in CI. Where a harness lacks a feature, the adapter records the gap instead of inventing a key. The deeper per-harness reasoning lives on the harness matrix.

State machine & hooks

Each command declares its stages; shipmates state turns them into a state machine, and a tool hook makes the gates real.

A command's stages: frontmatter (with loopback targets and a tool→phase binding, tool_gates) defines a finite-state machine. The shipmates state engine validates each transition over a per-run .shipmates/run-<N>.json file, answering legal (exit 0), illegal (exit 1) or error (exit 2).

That is the whole trick: the same stages: that read as prose guidance become hard, unskippable gates at the tool boundary. The hook only ever blocks a run it can positively identify; anything ambiguous is allowed through.

The fallback: advisory where there's no hook

Hard enforcement needs a scriptable, blocking pre-tool hook. Seven of the eight supported harnesses have one. Zed does not.

When a harness has no blocking hook, Shipmates falls back to the advisory state machine. The crew and commands install and work exactly the same, and stages: still document the intended flow — but nothing hard-blocks an out-of-order tool call. The FSM is prompt-level guidance, not an enforced gate, just as it was everywhere before a hook was wired.

The honest scope, plainly: tool-boundary transitions are hard-enforced on hook-capable harnesses; judgment gates and hook-less harnesses stay advisory. For a hook-less harness the neutral alternative is an external orchestrator that drives shipmates state itself — a separate runner — but the in-harness default is simply this: enforced where a hook exists, advisory where it doesn't.

How it stays honest

Every target's output is byte-compared against a committed digest, and CI fails on drift.

Each adapter's payload is deterministic and checked against tests/payload-digests/<name>.sha256; the feature matrix is validated too, so adding a frontmatter key without registering it fails the build. The site you are reading is generated from the rendered Claude Code payload and gated the same way.

On enforcement specifically: claude-code ships the reference hook today (enforcement/hooks/claude-code/). Wiring an equivalent shim into the other six hook-capable adapters is in progress (#217) — until it lands, treat those as advisory in practice. Nothing here is described as tested on a harness Shipmates has not been run on.
