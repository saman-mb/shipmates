🌊 Harnesses

Harness matrix

Which harnesses the crew runs on, and what's coming next.

The installer knows eight harness roots, but known is not shipped: a payload is built for a harness only when we've verified it can keep every safety property the commands rely on.

The matrix

Shipped means harnesses/claude-code/ is built, committed, and installable — a byte-for-byte mirror of the canonical skills/ and agents/ trees. In development means the harness has a tracking epic and we're actively building its adapter. Planned means we intend to support it but haven't started. Today harnesses/ holds claude-code alone; the others are pending safety verification.

Why not yet?

Every one of the twelve commands ships disable-model-invocation: true — you start one by typing /ship-issue; the model never loads one on its own. These workflows create worktrees, push branches, and open pull requests, so the decision to start one stays with the captain.

Before we ship a payload for a new harness, we verify it has an equivalent guard. No other harness documents one yet, so the capability matrix holds back those payloads until we can confirm the safety property carries over. The moment a harness documents an equivalent, the matrix entry flips and a payload appears.

The four harnesses with tracking epics are in active development — their adapter stories include verifying this exact property. The mechanics of how the matrix works are on the architecture page.
