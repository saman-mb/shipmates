📦 Install

Install reference

Every flag, every scope, every path the installer touches.

The installer is a single Bash script, install.sh. Run it straight from the web, no clone required — everything below applies identically to a local ./install.sh from a clone.

Global install

One command, every project. Requires bash, curl, tar, and python3 (>= 3.9) — the installer compiles the payload from the canonical sources at install time.

curl -fsSL https://raw.githubusercontent.com/saman-mb/shipmates/main/install.sh | bash

Installs into ~/.claude (or $CLAUDE_CONFIG_DIR if you have it set), so the crew and the twelve commands are available in every project. Piped from the web there is no local copy to trust, so the script downloads the main-branch tarball first; run from a clone it copies the files sitting next to it instead.

Project-scoped install

One repo only.

curl -fsSL https://raw.githubusercontent.com/saman-mb/shipmates/main/install.sh | bash -s -- --project /path/to/repo

Installs into /path/to/repo/.claude. A bare --project with no path scopes to the current directory's ./.claude. The project base directory is created if it doesn't exist yet.

What the installer does

  • Compiles the payload from the repository's canonical/ sources with tools/export.py, into a temporary directory it removes on exit. Copies the resulting twelve skills/<name>/ trees whole — whatever a skill bundles (references/, scripts/, assets/) comes along with its SKILL.md — and the twelve agents/*.md personas into the target root. On opencode the same twelve commands are written as flat commands/<name>.md files instead. Subagents ship to claude-code and opencode only — those are the two harnesses with a documented native subagent directory; for the rest they are skipped with a note.
  • Records a manifest at <target>/shipmates/manifest: one line per file with its SHA-256, so later runs can tell Shipmates' files from yours. Every harness root gets its own manifest, so --uninstall works per harness.
  • Re-installing skips files that are already identical and upgrades ones only Shipmates touched — without making backups.
  • A file you wrote or edited is backed up to <file>.bak-<timestamp> first, and if its frontmatter name: says it is a different agent or skill than the one replacing it, you get a loud warning.
  • Stale flat commands/<slug>.md files from the pre-skills layout are swept aside to .bak-<timestamp> so they can't shadow the new skills/<slug>/SKILL.md (Claude Code roots only). Commands you wrote yourself are never touched.

Flags

FlagDefaultEffect
--project [PATH]globalInstall into PATH/.claude (or ./.claude when PATH is omitted).
--dir PATHglobalInstall into an explicit .claude directory — pins the root exactly, so the harness choice changes nothing there.
--harness NAMEclaude-codeInstall into another harness's root. Repeatable, or pass all. Composes with --project; --dir pins a single root, so it takes one harness at a time. Only claude-code and opencode build today. Naming one of the other six explicitly is refused before any directory is created; all installs what it can and skips the rest with a note.
--uninstallinstallRemove the files Shipmates installed, using the manifest; restores your .bak-* originals.
--forceoffSkip SHA checks, overwrite everything — escape hatch for a wrong manifest or a clean slate. Still backs up first.

opencode takes the twelve as flat commands/<name>.md files rather than skill directories. That is a safety decision, not a formatting one — opencode's skills are model-invoked and its SKILL.md has no disable-model-invocation equivalent, so commands/ is what keeps the twelve user-invoked only. The reasoning is on the harness matrix.

codex and zed share a root — installing to both lands in the same place by design; the second run simply reports every file unchanged, against the same manifest. Which of these the installer can actually build for today is a separate question — see the harness matrix. Today that is claude-code and opencode; the other six are refused.

Verify

ls ~/.claude/agents
ls ~/.claude/skills
cat ~/.claude/shipmates/manifest

You should see twelve .md files in agents/, twelve directories in skills/ each holding a SKILL.md, and a manifest listing every installed file with its SHA-256. If a skills/ or agents/ directory was created for the first time, restart Claude Code so it picks them up — then run /ship-issue <issue#>.

For an opencode install, check the two directories it uses instead:

ls ~/.config/opencode/agents
ls ~/.config/opencode/commands
cat ~/.config/opencode/shipmates/manifest

Twelve .md files in each. Note that opencode has not been verified at runtime — the payload format was checked against opencode's parsing source and first-party docs, but no live run has confirmed that the agents resolve or that /ship-issue completes. See the harness matrix.

Uninstall

curl -fsSL https://raw.githubusercontent.com/saman-mb/shipmates/main/install.sh | bash -s -- --uninstall

Uses the manifest to delete only what Shipmates put there and left untouched; anything you modified is left alone. When a file is removed and a .bak-<timestamp> exists beside it, your original is restored. Works offline — no tarball download just to remove files.

Without a manifest (installs from before the manifest existed) it falls back to the old behaviour — deleting only payload-identical files — and says so loudly. A manifest that fails validation is corrupt: uninstall refuses, and tells you to either delete it (rm ~/.claude/shipmates/manifest) and re-run for a name-based uninstall, or pass --force to take the same fallback directly.
