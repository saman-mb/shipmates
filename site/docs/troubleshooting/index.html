🩺 Troubleshooting

Troubleshooting

Symptom → cause → fix.

Every answer below describes the installer's actual behaviour — when in doubt, read what it printed: it says what it skipped, backed up, or refused, and why.

On this page

  • Install problems
  • Runtime problems
  • Upgrade problems

Install problems

install.sh: Permission denied

Cause: you saved the script and ran it as ./install.sh without the execute bit. Fix: run it through Bash instead — bash install.sh — or set the bit once with chmod +x install.sh. Piped installs (curl … | bash) never hit this, because Bash reads the script from stdin.

install.sh: No such file or directory

Cause: the file isn't where you said it was — the download failed, or wrote to a different directory. Fix: check it exists (ls -l install.sh) and re-download with the failure flags, so an HTTP error fails the transfer instead of saving an error page: curl -fsSL -o install.sh https://raw.githubusercontent.com/saman-mb/shipmates/main/install.sh, then bash install.sh. Or skip the file entirely and pipe straight into Bash, per the install reference.

Shipmates: 'python3' (>= 3.9) is required

Cause: the installer compiles the payload from the canonical sources at install time, so python3 is required alongside curl and tar. You either have no python3 on PATH, or one older than 3.9. Fix: check with python3 --version, then install or upgrade Python 3 (macOS: brew install python; Debian/Ubuntu: sudo apt install python3). If a newer Python is already installed but not first on PATH, put it there and re-run. Nothing is written before this check, so a failed install leaves no partial state.

Skills don't load after install

Cause: Claude Code scans its skills/ and agents/ directories at startup, so a first-time install isn't visible to an already-running session. Fix: restart Claude Code — the installer prints exactly this reminder when it creates either directory. If they still don't load, verify the files landed where you expected (see Verify in the install reference).

Runtime problems

/ship-issue doesn't resolve

Cause: the skill isn't where the harness looks, or its identity broke — the Agent Skills standard requires the frontmatter name: to equal the parent directory name, so skills/ship-issue/SKILL.md must declare name: ship-issue. Fix: check ~/.claude/skills/ship-issue/SKILL.md exists (global), or .claude/skills/ship-issue/SKILL.md for a project-scoped install. Missing → re-run the installer. Hand-edited name: → restore it to match the directory.

Manifest is corrupt / fails validation

Cause: <target>/shipmates/manifest was hand-edited, truncated, or comes from an incompatible version — a manifest is a deletion instruction list, so anything suspicious stops the installer from trusting it. Fix: installing is safe — it treats the corrupt manifest as a fresh install, backs up every overwrite, and writes a fresh manifest at the end. Uninstalling refuses against a corrupt manifest: either delete it (rm ~/.claude/shipmates/manifest) and re-run --uninstall for the name-based fallback, or pass --force to take that fallback directly.

.bak-* files everywhere

Cause: you edited files Shipmates also ships, and the installer moved your versions aside before overwriting — it never deletes your work. Fix: nothing to fix; the backups are the safety net. Restore any of them by hand, e.g. mv 'skills/ship-issue/SKILL.md.bak-20260728103000' 'skills/ship-issue/SKILL.md'. --uninstall restores the newest matching .bak-* automatically when it removes a file.

Legacy commands/*.md shadowing the skills

Cause: installs from before the skills layout shipped flat commands/<slug>.md files, and a stale copy shadows the new skills/<slug>/SKILL.md. Fix: none needed — install and --uninstall both sweep those aside to .bak-<timestamp> automatically (Claude Code roots only; the sweep covers only the target you ran against, so re-run without --project/--dir to clear a global install too). Commands you wrote yourself are never touched.

Upgrade problems

An upgrade reset my customizations

Cause: your edited file differed from both the payload and the manifest, so the installer backed it up to .bak-<timestamp> and installed the new version. Files identical to the manifest upgrade in place with no backup; files identical to the payload are skipped entirely. Fix: merge your changes back from the .bak-* next to the file. If you want a clean slate regardless of SHA state, re-run with --force — it overwrites everything, and still backs up first.

Installed into the wrong harness

Cause: --harness selects the install root, and the default is claude-code — a forgotten flag installs there. Fix: every harness root gets its own manifest, so uninstall from the wrong one without touching the right one — install.sh --harness <name> --uninstall — then reinstall with the correct --harness. An unknown harness name is a hard error that lists the known names before anything on disk is touched.
